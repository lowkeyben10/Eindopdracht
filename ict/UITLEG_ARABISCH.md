# شرح مشروع GridWatch 2030 بالعربية

## ما هو هذا المشروع؟
هذا المشروع **بيئة تجريبية** لشبكة كهرباء خيالية اسمها GridWatch 2030. الهدف منها أن نُحاكي (نُقلّد) أحداثًا مثل:
- تسجيل دخول ناجح أو فاشل
- محاولات اختراق (إدخال كلمة سر خاطئة عدة مرات)
- أخطاء في البرنامج
- توقف أحد الأجهزة (الحاويات)
- ضغط كبير على النظام

كل حدث يُكتب في **ملف سجل** (`logs/app.log`). لاحقًا يستخدم طلاب HBO هذا الملف لتعلّم المراقبة والأمن السيبراني.

---

## المشروع مثل مطعم صغير 🍽️
| الجزء | المثال | الملف |
|---|---|---|
| الموقع (الصفحات) | صالة المطعم التي يراها الزبون | `web/templates/` و `web/static/style.css` |
| الخادم (البرنامج) | الطبّاخ الذي يعمل كل شيء | `web/app.py` |
| قاعدة البيانات | المخزن الذي نحفظ فيه كل شيء | حاوية `database` (PostgreSQL) |
| ملف السجل | دفتر يومي يُكتب فيه كل ما يحدث | `logs/app.log` |
| الـ API | شبّاك تطلب منه الحواسيب المعلومات مباشرة | العناوين التي تبدأ بـ `/api/` |
| Docker | صندوق نقل يحمل كل شيء ويعمل على أي حاسوب | `docker-compose.yml` و `web/Dockerfile` |

---

## شرح كل ملف
- **`docker-compose.yml`**: يصف **الحاويتين** (containers):
  1. `webapp`: الموقع والـ API، وتعمل على المنفذ 5000.
  2. `database`: قاعدة البيانات PostgreSQL.

  ويقول أيضًا: احفظ ملفات السجل في مجلد `logs` على حاسوبك، وانتظر حتى تصبح قاعدة البيانات جاهزة.
- **`web/Dockerfile`**: وصفة لبناء حاوية الموقع: خذ Python، ثبّت المكتبات، ثم شغّل `app.py`.
- **`web/requirements.txt`**: قائمة المكتبات المطلوبة (Flask وغيرها).
- **`web/app.py`**: قلب المشروع. فيه خمسة أجزاء:
  1. **التسجيل (Logging)**: يكتب كل حدث بالشكل `2026-04-01 09:14:22 INFO User admin logged in`.
  2. **قاعدة البيانات**: ينشئ الجداول `users` و `stations` و `events` و `sensor_data`، ويملؤها بأمثلة مثل محطة Arnhem و Zwolle و Eemshaven.
  3. **الصفحات**: تسجيل الدخول، والتسجيل، والمحطات، والصيانة، والأعطال، ومركز الاختبار.
  4. **الـ API**: يعطي البيانات بصيغة JSON.
  5. **الأخطاء والتشغيل والإيقاف**: يكتب في السجل عند حدوث خطأ، وعند تشغيل البرنامج وإيقافه.
- **`web/templates/`**: صفحات HTML (تصميمك الأصلي نفسه، مع صفحات جديدة).
- **`README.md`**: التوثيق بالهولندية للمعلّم: طريقة التثبيت، والحاويات، والسيناريوهات.

## طريقة التشغيل
1. افتح برنامج **Docker Desktop**.
2. افتح الطرفية (Terminal) في مجلد المشروع واكتب:
   <div dir="ltr">

   ```
   docker compose up -d --build
   ```
   </div>
3. افتح المتصفح على العنوان **http://localhost:5000**
4. سجّل الدخول باسم المستخدم `admin` وكلمة السر `GridWatch2030!`

للإيقاف اكتب: `docker compose down`

## السيناريوهات وكيف تجرّبها
| # | السيناريو | ماذا تفعل | ماذا يظهر في السجل |
|---|---|---|---|
| 1 | دخول ناجح | ادخل باسم `admin` وكلمة السر الصحيحة | `INFO User admin logged in` |
| 2 | دخول خاطئ عدة مرات | جرّب `welkom123` ثم `test123` ثم `admin123` | `WARN Invalid password` ثم `Possible brute force attack` |
| 3 | طلبات API كثيرة | نفّذ الأمر الموجود في صفحة مركز الاختبار (50 طلبًا) | `INFO GET /api/stations` ثم `WARN High API traffic` |
| 4 | خطأ في البرنامج | اضغط زر **Genereer foutmelding** | `ERROR Test exception generated` |
| 5 | توقف الحاوية | اكتب `docker stop webapp` | `INFO Application stopped` |
| 6 | ضغط كبير | اضغط زر **Genereer 1000 sensorrecords** | `Load test finished` و `High temperature` |

يمكنك رؤية آخر 25 سطرًا من السجل في أسفل صفحة **Testcentrum** (مركز الاختبار).

## كلمات مهمة
- **Container (حاوية)**: صندوق صغير يعمل فيه برنامج واحد.
- **Database (قاعدة بيانات)**: مكان منظّم لحفظ المعلومات.
- **API**: طريقة تتكلم بها الحواسيب مع بعضها.
- **Log (سجل)**: دفتر يومي للبرنامج.
- **Brute force**: محاولة تخمين كلمة السر مرات كثيرة.
- **Hash**: كلمة السر بعد تشفيرها، حتى لا يقرأها أحد.
